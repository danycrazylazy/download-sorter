# Download Sorter

Небольшая утилита на Python, которая распределяет файлы из выбранной папки по подпапкам в соответствии с расширениями. По умолчанию программа использует папку `Downloads` текущего пользователя. Информация о выполненных перемещениях записывается в JSON-журнал и используется для обратного перемещения файлов.

Программа рассчитана на локальное использование. Она не загружает файлы в интернет и не требует сторонних Python-пакетов.

## Возможности

- Сортирует файлы, находящиеся непосредственно в корне исходной папки.
- Создаёт подпапки по расширениям: `pdf`, `jpg`, `zip` и т. д.
- Приводит расширение к нижнему регистру: например, `REPORT.PDF` попадёт в `pdf`.
- Перемещает файлы без расширения в папку `no_extension`.
- При совпадении имён подбирает свободное имя с суффиксом `_1`, `_2` и далее.
- Пропускает каталоги, символические ссылки и элементы, имена которых начинаются с точки.
- Записывает исходный и конечный пути перемещённых файлов в `sort_log.json`.
- Поддерживает обратное перемещение по журналу в режиме `rollback`.
- Содержит BAT-файлы для запуска сортировки и отката в Windows.
- Работает на стандартной библиотеке Python; установка дополнительных пакетов не требуется.

## Требования

- Python 3.6 или новее (в исходном коде используются f-строки). Для новых установок рекомендуется актуальная поддерживаемая версия Python 3.
- Windows, macOS или Linux.
- Права на чтение и перемещение файлов в исходной папке, а также на создание и запись журнала рядом со скриптом.

В проекте нет `requirements.txt`: сторонние зависимости отсутствуют.


3. Откройте терминал в распакованной папке проекта.

## Какую папку обрабатывает программа

По умолчанию в начале `classifierscript.py` указано:

```python
SOURCE = Path.home() / "Downloads"
```

`Path.home()` получает домашнюю папку **текущего пользователя компьютера**. Поэтому программа не привязана к учётной записи автора репозитория. Она ожидает, что внутри домашней папки есть каталог с именем `Downloads`.

Если у вас папка загрузок находится в другом месте или называется иначе, измените значение `SOURCE` в `classifierscript.py`. Например:

```python
# Windows
SOURCE = Path(r"D:\Files\Downloads")

# macOS или Linux
SOURCE = Path("/home/username/Downloads")
```

Во втором примере замените путь на фактический путь к своей папке. После изменения сохраните файл.

Если исходная папка не существует, программа выведет сообщение о том, что папка не найдена, и завершит соответствующую операцию.

## Запуск на Windows

### Сортировка

Самый простой способ — дважды щёлкнуть `sort.bat`.

Также можно открыть CMD или PowerShell в папке проекта и выполнить:

```powershell
py -3 classifierscript.py
```

Если команда `py` недоступна, попробуйте:

```powershell
python classifierscript.py
```

`sort.bat` сначала проверяет наличие Windows Python Launcher и доступность Python 3 через `py -3`. Если этот вариант недоступен, BAT-файл пытается использовать команду `python`.

### Откат

Дважды щёлкните `rollback.bat` или выполните команду:

```powershell
py -3 classifierscript.py rollback
```

При отсутствии команды `py`:

```powershell
python classifierscript.py rollback
```

## Запуск на macOS и Linux

Откройте терминал в папке проекта.

Сортировка:

```bash
python3 classifierscript.py
```

Откат:

```bash
python3 classifierscript.py rollback
```

BAT-файлы предназначены для Windows. На macOS и Linux запускайте Python-скрипт командами выше.

## Пробный запуск без перемещения файлов

В начале `classifierscript.py` есть параметр:

```python
DRY_RUN = False
```

Чтобы сначала посмотреть, какие действия программа собирается выполнить, измените его на:

```python
DRY_RUN = True
```

Затем запустите сортировку обычным способом. Программа выведет предполагаемые перемещения с префиксом `[dry]`, но не будет перемещать файлы и сохранять журнал этой пробной операции.

После проверки верните значение `DRY_RUN` на `False`, чтобы разрешить реальные перемещения.

Обратите внимание: `DRY_RUN` применяется и к откату. В этом режиме откат только выводит предполагаемые действия; файлы не перемещаются, папки не удаляются, журнал не обновляется.

## Как работает сортировка

1. Программа проверяет, существует ли исходная папка.
2. Загружает `sort_log.json`, если файл журнала существует.
3. Перебирает элементы непосредственно в корне исходной папки в сортированном порядке.
4. Пропускает каталоги, символические ссылки, скрытые элементы (имена, начинающиеся с `.`) и файл с именем `sort_log.json`.
5. Берёт расширение файла, переводит его в нижний регистр и использует его как имя папки назначения. Если расширения нет, используется `no_extension`.
6. Если в корне исходной папки уже существует файл с именем будущей папки назначения, соответствующий файл пропускается.
7. Если файл с таким именем уже находится в папке назначения, программа подбирает имя с числовым суффиксом: `filename_1.ext`, `filename_2.ext` и т. д.
8. Перемещает файл и добавляет его исходный и конечный пути в журнал.
9. После завершения прохода пытается сохранить журнал.

Программа не обходит вложенные каталоги рекурсивно. Файлы, которые уже находятся внутри подпапок исходной папки, повторно не сортируются.

## Как работает откат

Откат запускается с аргументом `rollback`. Также распознаются аргументы `undo` и `откат`.

Программа проходит по записям журнала в обратном порядке. Для каждой записи она:

- проверяет, существует ли файл по сохранённому конечному пути;
- проверяет, свободен ли исходный путь;
- возвращает файл, если конечный файл существует, а исходный путь свободен;
- пропускает файл, если он уже отсутствует по записанному пути;
- оставляет запись в журнале, если исходный путь уже занят или при перемещении возникла ошибка.

После возврата файлов программа пытается удалить папки, которые ранее были созданы для сортировки. Удаляются только пустые папки. Если в папке остались другие файлы или каталоги, она сохраняется.

Откат использует пути, записанные в журнале. Не переносите файлы вручную и не редактируйте журнал между сортировкой и откатом, если рассчитываете на автоматический возврат.

## Журнал операций и конфиденциальность

Файл `sort_log.json` создаётся рядом с `classifierscript.py`. В нём хранятся два списка:

- `moves` — записи с полями `from` и `to`, содержащие исходный и конечный пути перемещённых файлов;
- `dirs` — пути папок, которые программа создала во время сортировки.

Журнал нужен для отката. Не удаляйте его до тех пор, пока он может понадобиться.

**Не публикуйте `sort_log.json` в открытом репозитории и не отправляйте его посторонним без проверки.** В нём могут находиться имя пользователя операционной системы, локальные пути и имена ваших файлов. Файл уже добавлен в `.gitignore`, поэтому Git не должен предлагать его для обычного коммита.

Если журнал повреждён или недоступен, текущая реализация выводит сообщение и возвращает пустую структуру журнала. В таком случае не запускайте новую сортировку, если вам важен откат предыдущих перемещений: сначала сохраните копию повреждённого файла и разберитесь с журналом.

## Важные ограничения и меры предосторожности

- Программа **перемещает**, а не копирует файлы. Перед первым запуском рекомендуется сделать резервную копию важных данных.
- Обрабатываются только файлы непосредственно в исходной папке; вложенные папки не обходятся.
- По умолчанию используется путь `~/Downloads`. Проверьте его и при необходимости измените `SOURCE` до запуска.
- Журнал хранится рядом со скриптом. Убедитесь, что у программы есть право создавать и изменять файлы в этой папке.
- Журнал сохраняется после завершения прохода сортировки, а не после каждого отдельного перемещения. Если программа или компьютер аварийно завершит работу во время сортировки, часть уже перемещённых файлов может не попасть в журнал.
- Если сохранить журнал не удалось, программа выводит сообщение, но сама сортировка уже могла переместить файлы. Проверьте вывод консоли и состояние папок.
- При повреждённом журнале программа не выполняет полноценное восстановление его содержимого.
- При откате файлы не перезаписываются, если исходное место уже занято.
- Если файл, записанный в журнале, больше не найден по конечному пути, запись о нём не сохраняется в обновлённом журнале после отката.
- Одновременный запуск нескольких копий программы с одним и тем же журналом не координируется. Не запускайте сортировку и откат параллельно.
- В программе нет графического интерфейса и автоматического планировщика.

## Устранение неполадок

**Сообщение о том, что папка не найдена**

Проверьте значение `SOURCE` в `classifierscript.py`. Укажите существующую папку и повторите запуск.

**Windows сообщает, что Python не найден**

Установите Python 3. При установке Python для Windows включите добавление Python в `PATH`; также можно установить Python Launcher. После установки закройте и заново откройте терминал.

**Файл не перемещается из-за занятого имени**

Если имя целевой папки уже занято обычным файлом, программа пропустит этот исходный файл. Если занято имя самого файла в папке назначения, программа попробует подобрать имя с суффиксом.

**Откат сообщает, что исходное имя уже существует**

Программа не перезаписывает существующий файл. Освободите исходное имя, предварительно убедившись, что существующий файл можно переместить, и повторите откат.

**Журнал недоступен или повреждён**

Не удаляйте и не заменяйте его случайным пустым файлом. Сделайте копию журнала и проверьте, остались ли в нём записи о нужных перемещениях.
