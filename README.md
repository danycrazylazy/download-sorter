# Download Sorter

Download Sorter — консольная утилита на Python, которая перемещает файлы из указанной папки в подпапки, названные по расширениям файлов. Выполненные перемещения записываются в JSON-журнал; по этому журналу можно запустить обратное перемещение.

## Возможности

- Сортировка файлов, находящихся непосредственно в исходной папке.
- Создание подпапок по расширениям файлов.
- Приведение расширений к нижнему регистру.
- Перемещение файлов без расширения в папку `no_extension`.
- Добавление числового суффикса к имени файла, если такое имя уже занято в папке назначения.
- Сохранение исходных и конечных путей в `sort_log.json`.
- Обратное перемещение файлов по журналу в порядке, обратном сортировке.
- Пробный режим `DRY_RUN`, при котором программа показывает предполагаемые действия без перемещения файлов.

## Требования

- Python 3.6 или новее.
- Windows, macOS или Linux.

Используются только модули стандартной библиотеки Python. Устанавливать дополнительные пакеты через `pip` не требуется.

## Установка

1. Скачайте ZIP-архив репозитория через **Code → Download ZIP** и распакуйте его либо клонируйте репозиторий:

   ```bash
   git clone <URL-репозитория>
   ```

2. Убедитесь, что Python 3 установлен.
3. Откройте терминал в папке проекта.
4. Настройте исходную папку, если стандартный путь вам не подходит (см. раздел «Настройка»).

Дополнительная установка зависимостей не требуется.

## Настройка

В начале `classifierscript.py` находятся параметры:

```python
SOURCE = Path.home() / "Downloads"
SCRIPT_DIR = Path(__file__).parent
LOG_FILE = SCRIPT_DIR / "sort_log.json"
DRY_RUN = False
```

`SOURCE` — папка, из которой программа берёт файлы. По умолчанию это каталог `Downloads` внутри домашней папки текущего пользователя. Программа ожидает именно каталог с таким именем и не определяет автоматически фактическое расположение системной папки загрузок.

Если папка находится в другом месте или называется иначе, замените значение `SOURCE` на свой путь. Например:

```python
# Windows
SOURCE = Path(r"D:\Files\Downloads")

# macOS или Linux
SOURCE = Path("/home/username/Downloads")
```

Укажите существующую папку. Если `SOURCE` не существует, программа выведет сообщение и не выполнит сортировку.

`LOG_FILE` задаёт расположение журнала. По умолчанию `sort_log.json` создаётся в той же папке, что и `classifierscript.py`. Сохраняйте журнал рядом со скриптом: он необходим для отката.

`DRY_RUN` управляет пробным режимом. По умолчанию установлено `False`, то есть операции выполняются с перемещением файлов. Для предварительного просмотра действий измените значение на `True`.

## Использование

### Windows

Для сортировки дважды щёлкните `sort.bat` или выполните в терминале из папки проекта:

```powershell
py -3 classifierscript.py
```

Если команда `py` недоступна, можно выполнить:

```powershell
python classifierscript.py
```

В этом случае команда `python` должна запускать Python 3.

Для отката дважды щёлкните `rollback.bat` или выполните:

```powershell
py -3 classifierscript.py rollback
```

Либо, если используется команда `python`:

```powershell
python classifierscript.py rollback
```

BAT-файлы предназначены для Windows. Они сначала пытаются запустить Python через `py -3`, а затем используют команду `python`, если первый вариант недоступен.

### macOS и Linux

Откройте терминал в папке проекта.

Сортировка:

```bash
python3 classifierscript.py
```

Откат:

```bash
python3 classifierscript.py rollback
```

### Пробный режим

1. Откройте `classifierscript.py`.
2. Установите параметр:

   ```python
   DRY_RUN = True
   ```

3. Запустите сортировку или откат обычным способом.

В пробном режиме программа выводит предполагаемые перемещения с префиксом `[dry]`. Файлы не перемещаются, папки не создаются и не удаляются, журнал не обновляется. После проверки верните `DRY_RUN = False`, чтобы выполнять операции фактически.

## Как выполняется сортировка

1. Программа проверяет наличие папки `SOURCE`.
2. Загружает `sort_log.json`, если он существует.
3. Перебирает элементы непосредственно в корне `SOURCE` в отсортированном порядке.
4. Пропускает каталоги, символические ссылки, элементы, имена которых начинаются с точки, и элемент с именем `sort_log.json`.
5. Определяет расширение файла, приводит его к нижнему регистру и использует как имя папки назначения. Если расширения нет, используется папка `no_extension`.
6. Если путь папки назначения уже занят файлом, соответствующий файл пропускается и учитывается как ошибка.
7. Если в папке назначения уже есть файл с таким именем, программа подбирает свободное имя с числовым суффиксом: например, `report_1.pdf`, `report_2.pdf`.
8. Перемещает файл и добавляет исходный и конечный пути в журнал.
9. После завершения обработки пытается сохранить журнал.

После сортировки программа выводит количество перемещённых и пропущенных элементов, а также количество ошибок.

Расширение определяется по последней части имени файла: например, `archive.tar.gz` сортируется в папку `gz`. Вложенные папки не обходятся; обрабатываются только файлы непосредственно в `SOURCE`.

## Как выполняется откат

Откат запускается с аргументом `rollback`. Также скрипт распознаёт аргументы `undo` и `откат`.

Если в журнале нет записей `moves`, программа сообщает, что откатывать нечего. Иначе она читает записи `moves` из `sort_log.json` в обратном порядке и пытается переместить каждый файл из сохранённого конечного пути в исходный. В конце выводится количество возвращённых файлов и ошибок.

- Если файл по конечному пути не найден, программа пропускает его. Такая запись не переносится в обновлённый журнал.
- Если исходный путь уже занят, файл не перезаписывается, а запись остаётся в журнале для следующей попытки.
- Если при перемещении возникает ошибка, запись также остаётся в журнале.
- После попытки возврата программа удаляет только те папки, которые были созданы во время сортировки, и только если они пусты.
- Папки, которые удалить не удалось, остаются на месте и сохраняются в журнале.

Откат использует пути из журнала. Не удаляйте и не редактируйте `sort_log.json` между сортировкой и откатом.

## Журнал операций

`sort_log.json` создаётся рядом с `classifierscript.py`. В нём находятся два списка:

- `moves` — записи с полями `from` и `to`, содержащие исходный и конечный пути перемещённых файлов;
- `dirs` — пути папок, созданных программой во время сортировки.

Журнал сохраняется после завершения обработки папки, а не после каждого отдельного перемещения. Если программа или компьютер завершит работу аварийно до сохранения журнала, часть выполненных перемещений может не попасть в него.

Если журнал не удаётся прочитать или JSON в нём некорректен, программа выводит сообщение и использует пустой журнал. Если JSON корректен, но его верхний объект не является словарём или в нём нет ключей `moves` и `dirs`, программа также использует пустой журнал, но не выводит отдельное сообщение. Типы значений и содержимое отдельных записей полностью не проверяются. При последующей сортировке пустой журнал может быть сохранён поверх прежнего файла. Если в журнале есть история, необходимая для отката, сначала сделайте копию файла и не запускайте новую сортировку до выяснения причины ошибки.

Если сохранить журнал не удалось, программа выводит сообщение, но уже выполненные перемещения автоматически не отменяются. В таком случае проверьте расположение файлов и доступ к папке проекта.

Журнал содержит локальные пути и имена файлов. Не добавляйте `sort_log.json` в публичный репозиторий. Файл включён в `.gitignore`.

## Ограничения

- Программа перемещает файлы, а не копирует их.
- Обрабатываются только файлы непосредственно в `SOURCE`; вложенные каталоги не просматриваются.
- Имена, начинающиеся с точки, пропускаются. Проверка скрытого атрибута Windows отдельно не выполняется.
- При совпадении имени исходного файла во время отката существующий файл не перезаписывается.
- Если файл из журнала отсутствует по сохранённому конечному пути, соответствующая запись пропускается и не остаётся в обновлённом журнале.
- Журнал не сохраняется после каждого перемещения; аварийное завершение может оставить его неполным.
- Параллельная работа нескольких экземпляров с одним журналом не синхронизируется.
- У программы нет графического интерфейса и встроенного планировщика.
